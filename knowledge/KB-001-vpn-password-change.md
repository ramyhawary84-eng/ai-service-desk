# KB-001 – VPN connection fails after a password change

**Article ID:** KB-001  
**Category:** VPN / Network  
**Knowledge approval:** Approved  
**Automatic response allowed:** No  
**Purpose:** Support guidance for the final-project demo, limited to VPN connection failures following an intentional work-password change.

## When this article applies

An employee reports that their VPN stopped connecting after they intentionally changed their work password.

## Information to collect

- VPN application and operating system.
- Exact error message, excluding passwords or authentication codes.
- Whether normal internet access works.
- Whether other employees are affected.
- Business activity affected, available workaround, and time sensitivity.

## Initial troubleshooting

1. Check whether a normal website opens. If internet access also fails, investigate the network connection first.
2. Open the organization's approved VPN application. Disconnect any existing session and attempt to reconnect once.
3. If the official sign-in screen requests credentials, enter the current work password there. Never send passwords or authentication codes to the assistant.
4. If the connection still fails, stop repeated attempts and provide the error message to IT support.

## Escalation

- An unexpected password change or an unrequested MFA prompt requires security review.
- Account lockout or a repeated authentication failure requires technician assistance.
- Reports affecting multiple employees require assessment of a possible wider incident.
- Password resets, MFA changes, and administrative changes require a separate authorized process.

## Confirm the outcome

Ask the employee whether the VPN connects and the required business application is accessible.

If the issue persists, pass the collected information and attempted steps to the technician on the same ticket.
